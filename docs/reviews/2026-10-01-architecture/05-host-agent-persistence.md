# Host, agent, persistence and iPad boundaries

Reviewed baseline `59bc72668a33fba550c7d8ba14b8bb3ab28abe2a`. This is an assessment, not a change to the accepted LAN HTTP exposure, configured harness permissions, stack, or product contracts. Source observations and two bounded probes are distinguished below. The primary agent runs the baseline suites; this lane did not rerun them.

## Architectural strengths and actual round trips

The host has a useful, mostly explicit division of responsibility. `main.ts` constructs one `DocumentOwner` and passes executable paths into native calculators. Electron filesystem, dialog, process and credential APIs remain in `src/host`, main and CLI code. Shared model, input and browser code use data interfaces rather than importing Electron. [Main setup and IPC](https://github.com/osuushi/freac/blob/59bc72668a33fba550c7d8ba14b8bb3ab28abe2a/src/main.ts#L20-L33) and [nativeExecutable](https://github.com/osuushi/freac/blob/59bc72668a33fba550c7d8ba14b8bb3ab28abe2a/src/host/native-paths.ts#L6-L11) preserve this boundary. Preload exposes named methods; it does not expose arbitrary IPC channels or renderer-supplied filesystem writes. Most host handlers check both document window and main frame. The model handler checks main frame but lacks the document-window identity check used by the other handlers; the current single-window construction limits practical exposure.

An ordinary desktop edit crosses `freacModel` into `DocumentSession.model` and the same owner used by scripts. Scripts snapshot and typecheck exact source before acquiring modeling ownership, execute in a separate child, and submit serial operations through the bounded capability file channel. `ScriptSession.begin` asks the active renderer to atomically inspect gesture state and lock input. `ScriptEdits` retains one candidate, resolves decorator continuation, validates results, and accepts once; failure discards it. Script source enablement forks and adopts only on success. This gives manual and script paths shared calculators and decorator validators without a second document or saved command stream. The declaration/typecheck layer is guidance, not input validation; the operation/session validators remain essential. The shared ownership/validation differences and automatic cancellation publication race are covered by lane 1 rather than repeated here.

Save captures accepted geometry independently of camera and portable workspace bytes. `DocumentFiles.save` updates path and saved baseline only after the sibling-file write/rename succeeds. `workspaceSnapshot` checks file type, links, inode/time/size stamps and a second directory scan; `AgentWorkspace.saved` rescans after writing. Failed saves retain accepted geometry, identity and local files. Open parses and structurally validates first, prepares portable files privately, then materializes geometry through owner Open before adopting workspace/path. Kernel materialization occurs after the old agent has stopped, so materialization failure retains old geometry/files but can require explicit agent restart. A prepared root from a cancelled or failed Open is retained too; unlike old live roots it contains no unsaved edits, so its ownership could eventually distinguish disposable preparation from retained recovery without adding recovery infrastructure.

iPad shares this host rather than cloning it. `IPadSession` excludes desktop model/document/terminal access during handoff; `IPadServer` authenticates one peer and drains disconnect handlers before admitting another. Browser adapters preserve the typed frontend interfaces. Pending prompts reject on disconnect, scripts/calculations cancel, and a second cleanup pass discards results of non-cancellable work that finished during draining. RPC IDs correlate replies only. Computer file selection intentionally grants the paired surface computer-path authority; directory listing is not a sandbox. Public HTTP serving is restricted to built assets. These are coherent current decisions, not grounds for a new approval workflow.

## P2 — Natural harness exit loses child-process ownership

**Confidence: high; bounded runtime reproduction on this macOS host.** In [AgentProcess.start, onExit](https://github.com/osuushi/freac/blob/59bc72668a33fba550c7d8ba14b8bb3ab28abe2a/src/host/agent-process.ts#L39-L43), natural root exit clears `this.pty`. [AgentProcess.stop](https://github.com/osuushi/freac/blob/59bc72668a33fba550c7d8ba14b8bb3ab28abe2a/src/host/agent-process.ts#L62-L77) subsequently returns immediately when that handle is absent. Its descendant snapshot exists only when Stop catches the root alive. `AgentSession.request(read)` revokes the CLI connection after exit, but revocation does not stop filesystem writers.

The probe launched Custom `/bin/sh` with a redirected background writer that ignored HUP/TERM, then let the root exit normally. Status reported `running:false, exitCode:0`. After `stop()` and 350 ms, the child was still alive and file lines had grown from two to five. The probe killed its own child and removed its temporary directory in `finally`. This proves an ordinary background process can outlive the advertised session shutdown; it does not claim that all PTY children survive, or that arbitrary deliberately detached processes can always be contained.

Impact is specifically lifecycle correctness: New/Open/Close can take their final snapshot after “Stop” while a survivor continues writing the retained old workspace. The next document cannot receive its revoked CLI commands, which is good counterevidence, but later file writes can miss the final archive and disappear from dirty-state visibility after adoption.

Keep session process cleanup ownership separate from the currently live PTY handle. Select and verify an OS-appropriate bounded process-group/job strategy for the supported harness path, including natural exit; merely saving the root PID is insufficient after reparenting and PID reuse. Avoid a general supervisor project. Acceptance should use actual Custom terminal commands that leave both normal and HUP-resistant writers, let the harness exit, then New/Open/Close with Save. Verify final writes and that owned children cannot write afterward. The existing `agent-process.test.ts` covers a live root ignoring TERM, not this root-already-exited case.

## P2 — Model-only Save can create an archive that Open refuses

**Confidence: high; codec probe plus source observation.** [writePortableArchive](https://github.com/osuushi/freac/blob/59bc72668a33fba550c7d8ba14b8bb3ab28abe2a/src/model/portable-archive.ts#L19-L29) returns version-1 JSON immediately when portable files are empty, bypassing the 64 MiB combined check. [readPortableArchive](https://github.com/osuushi/freac/blob/59bc72668a33fba550c7d8ba14b8bb3ab28abe2a/src/model/portable-archive.ts#L32-L36), native preparation and browser Open reject encoded input above 72 MiB.

A 73 MiB padded, syntactically valid model envelope produced 76,546,137 bytes successfully; reading those bytes rejected “Document is too large.” Adding one workspace byte instead made the writer reject at 64 MiB. This tests the byte invariant, not a realistic 73 MiB CAD workload or successful geometry validation. Real exact BRep documents can grow; the failure does not depend on the padding field being meaningful geometry.

The native save path would then adopt the path and clear its geometry baseline after successful writing. A later Open/relaunch cannot read that saved content. Existing portable tests cover ZIP expansion and small round trips but miss the model-only writer branch. Apply the existing limit before both format branches and make the raw reader honor the intended expanded-model limit consistently. No migration system is needed. Acceptance: codec tests around the limit, plus a native Save/Save As failure that preserves destination, path and Edited state. Keep browser/native codecs aligned.

## P2 — Host model transport can bypass document lifecycle authority

**Confidence: high from source; no end-to-end probe.** [IPadSession.request](https://github.com/osuushi/freac/blob/59bc72668a33fba550c7d8ba14b8bb3ab28abe2a/src/host/ipad-session.ts#L72-L85) casts unknown JSON to `ModelRequest`; desktop preload exposes the same request union. [DocumentSession.model](https://github.com/osuushi/freac/blob/59bc72668a33fba550c7d8ba14b8bb3ab28abe2a/src/host/document-session.ts#L144-L148) forwards `new` and `open` as well as ordinary edits. Those owner commands replace geometry/history without the host's file identity, workspace, agent termination and unsaved-work lifecycle.

For a saved document with a running agent, a direct model `{kind:"new"}` clears geometry but keeps the old path/workspace and live binding. A subsequent native Save targets the previous file; the old harness can edit the replacement geometry. This is an authority mismatch between two legitimate application APIs, not an assertion that pairing should grant less computer access. Normal native/iPad buttons use `DocumentSession.command`, so current pointer routes avoid the bypass; standalone web needs raw owner New/Open because it has no native document session.

Narrow the desktop/iPad model adapter to geometry/query requests and reserve replacement for `DocumentSession.command`/`DocumentFiles`. Validate the runtime envelope at that boundary rather than trusting TypeScript casts. Retain the full owner API for its internal file materialization and standalone web path. Acceptance should show raw replacement requests rejected by both host surfaces, ordinary New/Open preserving save/discard/cancel and workspace capture, and old agent channels revoked on actual replacement. This requires no revision or retry protocol.

## P2 — Computer Close during iPad editing bypasses tool completion

**Confidence: medium-high; source trace, interaction acceptance outstanding.** [DocumentSession.dispatch](https://github.com/osuushi/freac/blob/59bc72668a33fba550c7d8ba14b8bb3ab28abe2a/src/host/document-session.ts#L183-L191) treats desktop Close/Quit/update restart while remote control is active as listener shutdown followed by host `command`. Shutdown invokes `cancelRemote`, which cancels and discards unfinished candidates. By contrast, [runDocumentCommand](https://github.com/osuushi/freac/blob/59bc72668a33fba550c7d8ba14b8bb3ab28abe2a/src/model/native-file-controls.ts#L112-L124) completes a released interaction before the same leaving command. The persistence contract requires normal acceptance on Close/Quit/restart; disconnect's discard contract should not silently substitute for an intentional file action.

Concrete trigger: release an extrusion drag on iPad, then close the computer window or invoke computer Quit. The host disconnects before asking the active editor to finish, dropping the temporary extrusion. iPad-initiated close reaches the ordinary completion route; intentional Return to computer and unexpected disconnect remain valid discard cases.

Route intentional leaving commands through the active surface's existing completion path before revoking it, with the existing disconnect fallback if that surface disappears. Preserve a failed completion/cancel prompt and a usable document. Acceptance: real Pencil/pointer release, computer Close/Quit, Save/Cancel/Don't Save, one Undo for accepted extrusion, and interruption during completion. Existing iPad tests exercise reconnect with an open file prompt and return-to-computer, not this released-tool close case.

## Refactoring and verification limits

Prioritize the two reproduced lifecycle/round-trip faults, then tighten replacement authority and reconcile intentional remote close. Keep the current small host modules: none of the reviewed host source files exceeds 300 lines. `DocumentSession` at 295 lines is near the threshold and combines IPC attachment, file lifecycle, surface routing and scripting; the useful split is an active-surface adapter plus document lifecycle, only as these concrete fixes require it. `AgentSession` at 284 lines similarly joins harness launch and portable workspace lifecycle. Avoid extracting forwarding helpers solely to lower line counts.

Packaging correctly supplies native executable paths and shipped Electron-as-Node CLI dependencies, but Forge pruning explicitly retains `darwin-arm64` PTY artifacts. Windows/Linux remain build targets, not verified packages. No platform expansion is proposed in this review. Read existing portable, agent-process, connection, native-document and iPad acceptance sources as counterevidence; they were not executed here. Physical iPad, authenticated Codex, Windows/Linux process cleanup, large real BRep saves, and the remote intentional-close interaction remain unverified in this lane.
