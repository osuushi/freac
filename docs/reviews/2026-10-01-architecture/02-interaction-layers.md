# Interaction layers architecture review

Reviewed baseline: `59bc72668a33fba550c7d8ba14b8bb3ab28abe2a`, 2026-10-01. This is principally a static source review, with one focused browser helper probe, not complete interaction acceptance. I read the current overview/process, local brief, selection, edit-lifecycle, drawing-attachment, modeling-tool and transform contracts, and traced their implementation. No application acceptance suite or native calculation was run by this lane. Existing tests cited below were inspected as acceptance routes; their presence does not establish current passing behavior.

## Existing ownership and complete paths

The principal boundary is appropriate. `SketchEditor.display` (`src/sketch/editor.ts:115`) chooses the lease candidate or the rendering copy of accepted data; `ModelClient.request` (`src/sketch/model-client.ts:170`) excludes a second ordinary request while working, cancelling or scripting. `ActiveInteraction.acquire` (`src/sketch/active-interaction.ts:72`) grants one lease. Controllers gather intent and request backend geometry; they do not own independent accepted documents. `InteractionLease.capture/releaseCapture` (`active-interaction.ts:127/144`) also keeps deliberate pointer release from triggering its lost-capture cancellation. These mechanisms should survive refactoring.

A Line gesture starts through `PointerGestures.start` (`src/sketch/gestures.ts:87`) and `beginDrag` (`src/sketch/drag-state.ts:125`). A workspace without a saved sketch supplies an `emptySketch`; accepted document data is unchanged. Crossing the drag threshold resolves pending creation through `createGeometry` (`drag-state.ts:97`). `updateDrag` (`src/sketch/drag-update.ts:73`) computes geometry, quantities and attachment links. `GestureSolve.enqueue/drain` (`src/sketch/gesture-solve.ts:30/40`) holds one running calculation and the latest replaceable target. Pointer release waits, releases capture, flushes the last solve and accepts (`gestures.ts:222`); cancellation restores the saved typed targets and cancels preview (`gestures.ts:78`). Reselection routes through `selectHit` (`src/sketch/selection-input.ts:6`), with endpoint movement through `configurePointTargets` and `dragPoints`, and Transform through `transformSelected` (`src/sketch/selection-transform.ts:11`). This is an input-to-geometry-to-reselection path, rather than creation-only layering.

Extrusion begins by resolving ordered selected profiles/faces and acquiring a lease (`src/model/extrude-controls.ts:136`). `AxialDrag` captures the handle, projects pointer displacement and queues signed distance (`src/model/axial-drag.ts:41/74`). The controller owns distance, symmetry, draft, twist and target choices; its drain obtains a candidate (`extrude-controls.ts:195`). Pointer release resets the pointer and releases capture (`axial-drag.ts:88`), without accepting geometry. Enter/check, operation-aware selection or tool switching reaches `finish` (`extrude-controls.ts:223`), which accepts and hides consumed sketches only after success. Escape cancels preview and releases the lease (`extrude-controls.ts:247`). Accepted bodies can be selected through `ModelControls.bindCanvas` and typed modeling targets; subsequent operations resolve stable body/face/edge identities. This preserves the approved temporary extrusion after release.

Selection is substantially better bounded than the editor's size suggests. `SelectedTargets` (`src/sketch/selected-targets.ts:50`) owns one typed ordered sketch selection; `wholeCurves`, points and editor `selectionOwners` are queries. `transformSelected` deliberately moves endpoints as points and avoids treating rendering owners as whole curves. `choosePoints` (`src/sketch/point-selection.ts:47`) preserves existing encounter order when adding targets. `ModelSelection.choose` (`src/sketch/model-selection.ts:103`) preserves modeling order and `resolveOperation` supplies common eligibility; `tool-policy.ts:17` only chooses a preference. Keep these direct semantic helpers, including the first-selected subject/second-selected reference contract.

## Prioritized findings

### P2 — Buffered Transform handoff can outlive cancellation

**Evidence and trigger.** `installTransformHandoff` (`src/model/transform-handoff.ts:24–37`) buffers only pointermove/up while awaiting `finish()`, then replays pointerdown/click/movement (`:53–68`). `TransformBoxMove.start` duplicates that buffering (`src/model/transform-box-move.ts:128–145`) and creates a fresh lease afterward (`:154`). Neither buffer records pointercancel, blur or parent-signal abortion. Its ordinary blur/pointercancel listeners call `cancel` before a drag exists (`transform-box-move.ts:71–72`, `:275`), so they cannot retire the pending start. A slow scale acceptance followed by focus loss or cancelled touch can therefore resume as a move/anchor gesture after the physical gesture ended. The captured replay also uses press-time modifiers, despite intervening modifier changes.

**Smallest change.** Share only the buffered-pointer lifetime mechanism between these two current routes: latest coordinates/modifiers, released/cancelled state, listeners bound to both buffer and parent lifetime, and an explicit continuation validity check. Keep geometry completion and pointer interpretation in the existing controllers. Do not create a universal tool engine.

**Verification and acceptance.** A bounded headless probe imported the actual `installTransformHandoff` with a minimal editor, connected button and delayed finish promise. Both Chromium and WebKit replayed one pointerdown after each of pointercancel, blur and parent-signal abort. The initial press was intercepted; the count measures the subsequent replay. Browsers and the ephemeral Vite server were closed. This verifies helper continuation, without native geometry or physical focus loss. Next delay delivery of a real scale acceptance, start an arrow, anchor and Command-box handoff, then cancel before delivery. Assert no resumed interaction or extra edit; scale acceptance retains its established result. Cover completed fast release, numeric tap and modifier changes, including hidden Electron. **Confidence:** high for helper replay, medium for full-product consequences and the separate box route. **Counterevidence:** target-connected checks and ordinary lost-capture cancellation do not cover the wait interval.

### P2 — Workspace-entry policy is distributed and already inconsistent

**Evidence and trigger.** `ActiveInteraction.dragging` (`active-interaction.ts:39`) interprets a hard-coded kind list plus capture. `installWorkspaceSync.canEnterSketch` (`src/sketch/editor-workspace.ts:13`) carries another exclusion list; `ModelControls.enter` (`src/sketch/model-controls.ts:214`) carries a third. The settled `scale` lease is navigation-compatible but absent from both entry exclusions. `PlaneTargetInteraction.available/click` (`src/sketch/plane-targets.ts:54/85`) uses `canEnterSketch`, then directly calls `sketchEntry`; that callback (`editor-workspace.ts:27`) changes workspace and clears modeling targets without finishing/cancelling the scale lease. Conversely menu plane entry requires complete idleness (`src/sketch/plane-entry-tools.ts:13`). Thus the same intended workspace transition has different protection by entry route. This can leave a modeling preview active in a new sketch workspace.

**Smallest change.** Establish one editor-level workspace-entry decision and transition that either rejects or explicitly completes the current operation according to current approved behavior. Have plane patches, menu entry and sketch/face entry use it. Express the small current navigation/entry capabilities alongside lease acquisition, rather than adding kind names to several lists. Leave reference-picking overlays and tool-specific capture routing local.

**Acceptance.** With valid, invalid, empty and calculating scale/extrude/revolve previews, exercise canonical plane patch double-click, menu plane entry, selected sketch/face Enter and region double-click. Verify transition, retained selection, candidate retirement and Undo count. Include ordinary pan/orbit and explicit reference picks. **Confidence:** high on inconsistent static gates, medium on resulting UI exposure. **Counterevidence:** scale suppresses plain canvas clicks in capture (`scale-controls.ts:134`) and normal model clicks finish operations (`model-controls.ts:132`); the earlier-installed plane handler in `main.ts:88/111/151` is a distinct route requiring verification.

### P2 — Extract the existing preview scheduler invariant, not whole tool lifecycles

**Evidence.** Extrude, Face Offset, Revolve and Scale repeat pending/latest/running/valid state and drain/finish/cancel sequences (`extrude-controls.ts:158/195/223`, `face-offset-controls.ts:133/158/200`, `revolve-controls.ts:178/211/236`, `scale-controls.ts:154/174/188`). Their differences are meaningful: extrusion interrupts superseded work, face offset can return the last verified distance/selection, revolution retains a labelled last-good presentation, and scale can accept identity by ending without history. Sketch `GestureSolve` already separates scheduling from gesture interpretation.

**Risk and smallest change.** Late-result validity, cancellation-before-await, and cleanup-probe coordination must currently be repaired in several copies. Extract a bounded preview runner for one running request, one latest target, cancellation and settlement; migrate Extrude and Face Offset first because they already share `AxialDrag` and cleanup probing. Explicit caller decisions should govern interruption, stale presentation and accepted parameter feedback. Do not unify acceptance-on-release with acceptance-on-tool-completion or make widget input state a backend document.

**Acceptance.** Preserve `tests/ui-extrude-preview.mjs` real-kernel delayed-delivery scenarios, then add corresponding offset invalidation/cancellation and last-verified feedback cases. Include superseded success/failure, invalid numeric entry, cleanup expiry and rapid accept/cancel. **Confidence:** high architectural repetition; this is a maintenance priority, not evidence of a present geometry failure. **Counterevidence:** current controllers guard request identity/phase, and sketch/solid display policies deliberately differ.

### P3 — Make numeric-edit collaboration explicit; keep useful direct widget helpers

`SketchEditor` exposes mutable callback slots (`editor.ts:72/103–105`); Dimensions installs commit/cancel/focus (`src/sketch/dimensions.ts:56`), while PointerGestures installs in-drag editing (`gestures.ts:31`). Many consumers receive the entire editor although they need numeric-edit coordination, selection queries and projection. The dependency direction and initialization order are implicit; missing installation silently becomes a no-op. Prefer one named, typed numeric-edit collaborator passed at composition, with explicit gesture editing support, before dividing the editor into general services. Keep local quantity conversion, snapping, `AxialDrag`'s small callback bundle, widget geometry projection and ordinary typed requests direct. `ExtrudeWidget.update` (`src/model/extrude-widget.ts:84`) correctly computes display positions, while the controller owns accepted operation parameters.

Acceptance should cover numeric blur/Enter/Escape, Tab/Shift-Tab, field edits during dragging, Option numeric copying and disposal. Confidence is high on coupling, low on any current initialization defect: `main.ts:135–137` installs these dependencies consistently. The host globals in `ModelClient` (`model-client.ts:6–19`) belong at the transport seam; `controls.ts:17` fixture capability gating is a small host-aware composition leak, not a reason to move geometry or selection into Electron.

## Size warnings and sequencing

The reviewed lane exceeds the source-file warning in `editor.ts` (303 lines) and `body-edge-finish-controls.ts` (308). No examined named method/function was established above 80 lines; the dense gesture release and near-limit Transform controllers still merit responsibility review. Size alone is not a regression. Fix buffered handoff cancellation first, consolidate entry decisions second, then extract the scheduler after its behavior matrix is explicit. Numeric collaboration can follow; preserve one document owner, stable IDs, ordered targets, modifier contracts and tool-specific completion rules throughout.
