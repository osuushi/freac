# Document ownership and edit acceptance

Reviewed baseline: `59bc72668a33fba550c7d8ba14b8bb3ab28abe2a`. Scope: accepted data, candidates, typed model calls, serialized calculation/cancellation, snapshot history, and solver translation. This is a review proposal; it changes no interaction contract.

## Assessment

Freac has one accepted document and one ordinary snapshot history. The current design does not need replacement with command envelopes, public revisions, a service graph, or feature replay. Two concrete boundary defects deserve correction: cancellation is not checked at automatic publication, and acceptance validates less than Open/script processing. Both can be repaired inside the existing owner/store boundary.

I read the current ownership, lifecycle, solver, solids, and implementation topic documents, and the relevant existing FreeCAD reference chapters. Historical protocol prescriptions in those chapters were not treated as requirements. All source references below refer to the baseline. Primary reported typecheck and Biome passing; I did not run their full suites.

## Traced paths and strengths

**Sketch pointer edit.** `PointerGestures.submit` (`src/sketch/gestures.ts:116`) passes a temporary target and explicit `dragIntent` to `GestureSolve`. Its `enqueue/drain` (`src/sketch/gesture-solve.ts:30–53`) retain one running request and one replaceable target. Completed calculations may display while newer pointer input is pending; only the latest target can set `valid`. `flush` at line 55 waits before release acceptance. `PointerGestures.release` (`gestures.ts:222–281`) releases capture intentionally, waits for the last solve, closes its lease, and calls `SketchEditor.accept` only when both gesture and solved target are valid. Invalid final input is discarded rather than accepting an older preview.

`ModelClient.request/send` (`src/sketch/model-client.ts:170–237`) flush selection intent, set busy state immediately, expose the delayed 150 ms indication, and issue one typed call. `DocumentOwner.call` (`src/backend/document-owner.ts:85–132`) rejects overlapping mutations. `previewDocument` (`src/backend/document-preview.ts:18–54`) solves against accepted data; `solveSketch` (`src/backend/solve-sketch.ts:12–71`) validates target geometry, builds disposable solver inputs, checks independent residuals and exact targets, translates results back to curve IDs, and validates the resulting sketch. Explicit `accept` carries no replacement-document payload (`src/sketch/model-api.ts:53`); it accepts the owner's candidate.

Cancellation has strong ordinary ownership protection: `GestureSolve.cancel` (`gesture-solve.ts:59`) marks the gesture cancelled before awaiting backend cancellation; `InteractionLease.show` (`src/sketch/active-interaction.ts:123`) cannot restore a closing owner's preview. Native cancellation detaches replies, rejects pending calculation, kills the child, and waits for process drain (`src/backend/native-calculator.ts:74–99`). The generic calculator is justified by two current adapters, not hypothetical transport extensibility.

**Extrusion.** `ExtrudeControls.begin/queue/drain` (`src/model/extrude-controls.ts:136–212`) capture source intent and retain a modal interaction. `DocumentOwner.dispatch` (`document-owner.ts:239–243`) calculates into `candidate`; `SolidEdits.calculate` (`src/backend/solid-edits.ts:105–175`) materializes exact kernel output. Pointer release does not publish. `ExtrudeControls.finish` (`extrude-controls.ts:223–245`) waits, closes the lease, explicitly accepts once, and releases it. Cancel (`:247–264`) hides the preview, drains cancellation, then releases ownership. `materialize` (`src/backend/kernel-result.ts:36–122`) converts temporary predecessor correspondence to persistent document-local IDs; numerical/render indexes do not become model identities.

**History and scripts.** `DocumentStore.accept/undo/redo` (`src/backend/document-store.ts:65–101`) owns geometry snapshots and ordered selection snapshots in one attempted-operation history. Failed/no-op records do not clear Redo; new geometry releases superseded snapshots. `SelectionHistory` (`src/sketch/selection-history.ts:19–92`) buffers UI intent and restores workspace/targets without saving camera/tool state. `ScriptEdits` (`src/backend/script-edits.ts:31–98`) uses one temporary script candidate, shared calculators, and the same store acceptance; intermediate script steps are not a second accepted document. Its cancellation checks after awaited calculation and continuation are useful counterexamples to the defect below.

## 1. Automatic commits can publish after cancellation

**Priority P1; confidence high for owner behavior, frequency in ordinary UI unmeasured.**

Source observation: `DocumentOwner.cancelPreview` (`document-owner.ts:133–145`) sets `cancelling`, cancels calculators, and waits for `active.promise`; it does not prevent that promise from publishing. Automatic publication occurs after awaits in `accept` (`:147–160`), `deleteEntities` (`:282–292`), and Open (`dispatch:225–226`). `transform-bodies` and `delete-topology` invoke `accept` automatically (`:223`, `:243`). All are classified cancellable by `cancellableCalculation` (`src/sketch/calculation-state.ts:24–27`). There is no check of cancellation immediately before `store.accept`/document replacement. Explicit Accept correctly remains noncancellable and should preserve that behavior.

Concrete probe: using Node 24.15.0 and the compiled test-cache modules, I created a real native 20 × 10 × 10 prism through sketch Edit → Extrude → Accept. I gated `owner.decorators.continue` after the transform calculation, started `transform-bodies` translating +10 X, waited for that continuation, called `cancel-preview`, then released the gate. Both calls returned without error; `documentChanged` was true; center changed from approximately `[10,5,5]` to `[20,5,5]`; history recorded an applied `changed` transform. A second gated probe reproduced publication for immediate `delete-entities`.

This is an actual owner/kernel path with an injected timing boundary, not proof that a real QuickJS hook or pointer sequence triggers the race. Custom continuation currently awaits runtime initialization (`src/backend/decorator-session.ts:34–36`, `:78–80`), so the asynchronous boundary is present. Native work cancelled before it returns is already protected; reviewed cancellation tests cover that case. Synchronous postprocessing cannot receive cancellation while it occupies the event loop.

Smallest coherent repair: keep calculated documents local until publication; for cancellable automatic edits, check the existing cancellation state after all awaits and immediately before publication. Treat this as a simple calculation-versus-commit boundary in the owner, not a new request token/revision system. Open should use the same boundary. Do not make explicit Accept interruptible. `ScriptEdits.step` already checks `cancelled` after both awaited stages (`script-edits.ts:57–61`), so preserve its policy.

Acceptance route: reproduce the gated transform/deletion/Open boundary, asserting accepted object identity, selection, Undo/Redo and cancelled history remain unchanged; cover cancellation while native work runs and while postprocessing waits. Then verify actual Cancel/Escape during slow native tools and restart the next calculation. Existing real-native tests in `tests/preview-cancellation.test.ts` and `tests/calculation-cancellation.test.ts` remain relevant adjacent checks.

## 2. Accepted-document invariants differ by entry point

**Priority P2; confidence high, normal generated-ID collision probability low.**

Source observation: `DocumentStore.accept` (`document-store.ts:69`) validates individual sketches only. `validateDocument` belongs to Open (`src/backend/open-document.ts:39–86`) and checks document-wide IDs, planes, decorator definitions/instances and presentation entries. Script steps call it (`script-edits.ts:61`), but manual typed edits do not. `withSketch` (`src/sketch/document.ts:133–138`) upserts by sketch ID without checking another entity category. `withConstructionPlane` (`src/model/construction-plane.ts:12–23`) separately implements some cross-category identity checks, demonstrating validation policy is already duplicated and asymmetric.

Concrete probe: I accepted a construction plane with ID `duplicate`, then submitted a valid empty Sketch with the same ID through normal `DocumentOwner.call({kind:"edit", sketch})`. Both calls succeeded. `validateDocument(owner.view.data)` then threw `Invalid or duplicate document identity`. The accepted state therefore violates a rule its own Open path enforces. This is a typed owner API probe, not a ordinary UI collision; creation tools use random IDs. Nevertheless stable IDs are an ownership invariant, and the owner should not depend on every caller recreating it correctly.

Smallest coherent repair: move whole-document validation into a neutral backend validation module and invoke it at the store's publication boundary, retaining operation-specific semantic/native checks before that point. Remove redundant cross-category checks only after the common boundary covers them. This requires no schema generator and no repeated kernel inspection at every sketch acceptance. Add missing ID-shape/group identity checks only where current selection/reference semantics require them; avoid expanding into a general validation framework.

Acceptance route: owner-level duplicate cross-category and malformed-ID cases must reject without modifying accepted data, candidate lifecycle, selection or Redo. Valid manual sketch, plane, solid/decorator and script edits should pass the same publication rules; valid archives should retain their existing migration/inspection flow.

## Responsibility and size guidance

`DocumentOwner.dispatch` spans 87 lines including its declaration/closing brace (lines 195–281), above the 80-line warning. `editor.ts` has 303 lines, above the 300-line warning; `extrude-controls.ts` remains below it at 298. `checkResiduals` also exceeds 80 lines (`solver-residuals.ts:4–93`); `solverInput` spans 97 (`solver-input.ts:65–161`). The size alone is not a split rationale. The useful owner seam is calculation result versus publication policy, because the cancellation defect crosses several branches. Keep domain-specific calculations in their existing modules; centralize only the final accepted-state decision.

Several kind lists duplicate lifecycle policy in owner/client/interaction code. The renderer review covers their specific navigation effects. I checked the reported scale omission in `editor-workspace.ts:16–26`: `ScaleControls.events` captures canvas pointerdown/click/dblclick while its lease exists (`src/model/scale-controls.ts:134–145`), so the omission alone does not establish a reachable canvas bug. Avoid a broad capability registry until a concrete interaction requires one.

**Lower-priority hardening, not an observed corrupting consumer:** snapshots retain incoming object references (`document-store.ts:82–85`), and `data`/owner `view` return them directly (`:46–47`, `document-owner.ts:55`). Curve properties are readonly, but nested `Point`, `Vector`, and `PlaneFrame` are mutable (`src/sketch/planes.ts:1–7`), as are body display arrays (`src/model/body.ts:7–8`, `:30–31`). Thus “read-only view” is partly a convention for backend consumers. Transport cloning protects the renderer from mutating accepted objects; the inspected normal consumers use replacement geometry, and I found no accepted-array mutation. Prefer readonly nested geometry types at these boundaries and retain copy-on-edit discipline. Do not add blanket full-document cloning/freezing to every pointer update without a demonstrated need and cost measurement. Acceptance would include compiling current geometry constructors and a focused alias/snapshot test if this hardening is undertaken.

No pointer/browser/Electron flow was run in this lane. The focused probes exercised native prism calculation and owner publication, with controlled continuation timing; they created no production-source changes and closed their owned calculators. Performance consequences of full-document `JSON.stringify` equality/history retention remain unmeasured and are not presented as defects requiring a new history representation.
